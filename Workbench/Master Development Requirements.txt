# 3. Advanced Combined Task Management

Implement an advanced Combined Task Management system that allows administrators to configure multiple Combined Tasks at different task positions simultaneously.

### 3.1 Multiple Combined Task Positions

The backend must support multiple independently configured Combined Tasks within the same task sequence.

Example configuration:

| Combined Task | Task Position |
|---|---:|
| Combined Task 1 | 6 |
| Combined Task 2 | 9 |
| Combined Task 3 | 14 |
| Combined Task 4 | 16 |
| Combined Task 5 | 18 |

The system must automatically trigger the next configured Combined Task when the user reaches its assigned task position.

### 3.2 Automatic Task Triggering

Expected workflow:

1. The user starts completing their assigned tasks.
2. When the user completes Task 6, the next configured Combined Task is triggered at Task 9.
3. After completing the relevant task sequence, the next Combined Task is triggered at Task 14.
4. The same process continues for Task 16.
5. Finally, the Combined Task assigned to Task 18 is triggered.

The system must follow the configured task positions and execution order.

### 3.3 Dynamic Backend Configuration

Administrators must be able to:

- Add multiple Combined Tasks.
- Edit existing Combined Task configurations.
- Modify task positions.
- Rearrange the execution order.
- Update upcoming Combined Tasks.
- Remove or disable future Combined Task configurations where appropriate.
- Manage pending Combined Tasks independently.

### 3.4 Modify Upcoming Tasks During Execution

A particularly important requirement is that administrators must be able to modify the remaining Combined Tasks even after the first Combined Task has already been completed.

For example:

If a user has completed the Combined Task at position 6, an administrator must still be able to modify the configurations or positions of the remaining Combined Tasks at positions 9, 14, 16, and 18.

Changes must be applied according to a clearly defined effective time and execution state.

The system must maintain an accurate record of:

- Previous configuration.
- Updated configuration.
- Administrator responsible.
- Modification timestamp.
- Effective timestamp.
- Affected task positions.

### 3.5 Data Integrity and Task History Protection

**Critical Requirement:**

Modifying upcoming Combined Tasks must never negatively affect:

- Tasks already completed by users.
- Existing user account balances.
- Previous financial transactions.
- Historical task completion records.
- Previously generated transaction references.

Completed tasks must remain immutable from the perspective of historical records.

Future configuration changes must only affect eligible pending tasks.

Use appropriate database transactions, atomic updates, versioning, or other safeguards where necessary to prevent inconsistent task states.
